# TanStack Router and TanStack Form

Routing uses **TanStack Router** with file-based routes generated by its Vite plugin. Forms use **TanStack Form**. Together with TanStack Query they make one family that shares Zod 4 schemas through Standard Schema.

- Route files in `src/routes/` stay thin. Each holds only the path, `validateSearch` (a Zod schema), a loader that calls `queryClient.ensureQueryData` with Orval's generated `queryOptions`, and the feature component to render. `routeTree.gen.ts` is committed.
- View state worth bookmarking or handing to an agent, such as the selected Role, filters or the search query, lives in typed search params. Everything else is component state, and there is no global store.
- Each form validates with the Zod body schema Orval generates, through one app-level form hook (`createFormHook`) bound to the shadcn/ui Field parts.

## Considered Options

- **React Router 8 in data mode.** It is better known and has more examples. Rejected: outside framework mode, which this SPA doesn't use, its params and search params are much less strongly typed, and its loaders don't fit Query's `queryOptions` as directly.
- **React Hook Form with `@hookform/resolvers`.** It is the most widely used and works with the same Zod schemas. Rejected for consistency: it is a different style from the rest of the TanStack stack, and it needs an adapter where TanStack Form takes Standard Schema directly.

## Consequences

- Routes, loaders, search params and every form are written against TanStack APIs, so switching later means rewriting them all.
- `@tanstack/router-plugin` transforms with Babel, not the TypeScript API, so TypeScript 7 doesn't affect it.
